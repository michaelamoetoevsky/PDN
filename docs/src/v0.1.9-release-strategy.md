## What is DEFERRED to v0.2.0+ (Complex & Large)

### Image Store Architecture (Issue #37, Roadmap §4.4)
**Why complex**: Requires OCI blob storage, manifest cache, digest-addressed layers, pull/push transport.  
**Findings blocked by this**: 01-5 (`image ls` SIZE wrong — needs real image metadata), C2 persistence (stub→real).  
**Effort**: ~2 weeks, 8 files, new crate `pn-image-store`.  
**Decision**: Defer. Workaround for now: `podnext install <image>` creates runnable container directly.

### Login Polygon Expansion (Roadmap §10.2)
**Why complex**: 15 new flags (`--bind`, `--shared-tmp`, `--work-dir`, `--hostname`, `--detach`, etc), needs session persistence, PTY management, bind-mount validation.  
**Findings mentioning this**: 13-6 (documented `run` flags absent — but login is the real gap).  
**Effort**: ~1 week, touches `proot-distro-core` runtime layer.  
**Decision**: Defer to v0.2.0 "mobility target".

### Guest Environment Overhaul (/proc stubs, Batch G)
**Why complex**: 6 findings (11-6 to 11-11), touches `proot-distro-core/sysdata.rs`, needs `/sys` stub generation, `/dev` masking, tmpfs capping, timezone injection, umask policy, group filtering.  
**Effort**: ~4 days, risky (breaks existing guests if wrong).  
**Decision**: Defer. Current `/proc` stubs work for 90% of distros; edge cases documented as known-limitation.

### Transactional Install (01-3)
**Why complex**: Staging directory → atomic rename, needs rollback on failure, orphan GC, lock coordination.  
**Effort**: ~2 days.  
**Decision**: Defer. Workaround: `remove -f` cleans orphans manually.

### Post-Extract Smoke Test (01-4, signal 4)
**Why complex**: Needs to detect whether rootfs has `/bin/sh`, whether it's executable, whether proot can launch it (architecture/libc mismatch detection).  
**Effort**: ~1 day, false-positive risk.  
**Decision**: Defer. Documented limitation: "some distros unsupported on this architecture; check compatibility before installing."
