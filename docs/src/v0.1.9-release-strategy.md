# v0.1.9 Release Strategy: Stability and Honesty First

**Date**: 5 Nov 2026  
**Context**: 57 findings from audit swarm round 1. 2 critical findings went to manual dispatch. 55 findings went to 8 parallel agents.

---

## Mandate

> "perlu disisirkan bagian kompleks dan besar nya, agar dikerjakan setelah v0.1.9 di release"

v0.1.9 is **stability and honesty**, not feature expansion. All complex and large work moves to v0.2.0 or later.

---

## What Goes into v0.1.9: Stability and Honesty

### 1. Mandatory Critical Fixes
- **C1**: issue #41. Non-UTF-8 argv panic. The fix is `args_os()` and a unit test.
- **C2**: finding 01-1. The `image pull` stub is false. The fix is an honest rejection with a workaround.

### 2. High-Priority Safety: Batches A to C
- **Batch A**: storage. The batch fixes path traversal, validates volumes, and makes `rm` delete for real.
- **Batch B**: automation. The batch cleans the JSON output, fixes the stdin hang, and unifies the exit codes.
- **Batch C**: guest environment. The batch fixes DNS at `/etc/resolv.conf`, makes `/proc/mounts` honest, and isolates the host leak.

### 3. Documentation Honesty: Batch D
- Delete phantom commands. The phantoms are the `storage` family, exit codes 3 to 12, and fake `PN_*` environment variables.
- Mark stubs explicitly as experimental or unimplemented.
- Align the docs with the real CLI surface. No fictional flags remain.

### 4. Medium and Low Polish: Batches E to H, Selective
**Include if trivial**: less than 50 LOC and no new subsystems.
- **E**: The build hint uses the actual binary name. The install cleans orphan files.
- **F**: CLI alias fixes change `image rm` to `image remove`. The batch fixes wakelock case-sensitivity.
- **H**: The batch fixes bilingual help, moves prompts to stderr, and warns about conflicting flags.

**Defer if non-trivial**:
- **E**: Transactional install with a staging directory design. The signal-4 smoke test needs rootfs introspection.
- **G**: The `/proc` stub ecosystem has 6 findings. The work touches the `proot-distro-core` sysdata layer.
- **H**: The request timeout architecture needs a connection pooling design.

## What is Deferred to v0.2.0 and Later: Complex and Large

### Image Store Architecture: Issue #37, Roadmap section 4.4
**Why complex**: The work needs OCI blob storage, a manifest cache, digest-addressed layers, and pull and push transport.  
**Findings blocked by this**: 01-5 and C2 persistence. Finding 01-5 makes the `image ls` SIZE wrong and needs real image metadata. C2 persistence changes the stub to the real store.  
**Effort**: ~2 weeks, 8 files, new crate `pn-image-store`.  
**Decision**: Defer. Workaround for now: `podnext install <image>` creates a runnable container directly.

### Login Polygon Expansion: Roadmap section 10.2
**Why complex**: The work adds 15 new flags. The flags are `--bind`, `--shared-tmp`, `--work-dir`, `--hostname`, `--detach`, and others. The work needs session persistence, PTY management, and bind-mount validation.  
**Findings mentioning this**: 13-6. Finding 13-6 reports documented `run` flags as absent. The login flags are the real gap.  
**Effort**: ~1 week, touches `proot-distro-core` runtime layer.  
**Decision**: Defer to v0.2.0 "mobility target".

### Guest Environment Overhaul: /proc stubs, Batch G
**Why complex**: The work has 6 findings, from 11-6 to 11-11. The work touches `proot-distro-core/sysdata.rs`. The work needs `/sys` stub generation, `/dev` masking, tmpfs capping, timezone injection, an umask policy, and group filtering.  
**Effort**: ~4 days. The work is risky. A wrong change breaks existing guests.  
**Decision**: Defer. Current `/proc` stubs work for 90% of distros. The docs record edge cases as a known limitation.

### Transactional Install: finding 01-3
**Why complex**: The work changes a staging directory to an atomic rename. The work needs rollback on failure, orphan garbage collection, and lock coordination.  
**Effort**: ~2 days.  
**Decision**: Defer. Workaround: `remove -f` cleans orphans manually.

### Post-Extract Smoke Test: 01-4, signal 4
**Why complex**: The test must detect whether the rootfs has `/bin/sh`, whether `/bin/sh` is executable, and whether proot can launch it. The test detects an architecture or libc mismatch.  
**Effort**: ~1 day, false-positive risk.  
**Decision**: Defer. The documented limitation is: "some distros are unsupported on this architecture. Check compatibility before you install."
