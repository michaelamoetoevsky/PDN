===== podnext  --help =====
podnext (PRoot Distro Next) - Next-generation container & service orchestration platform.

========================================================================
1. SIMPLE & CORE DISTRO USAGE (Everyday proot-distro replacement):
========================================================================
podnext install debian:13                 # Install Debian 13 trixie distro
podnext login debian                      # Enter interactive container shell
podnext run debian -- apt update          # Run command directly in container
podnext list                              # List installed containers
podnext copy debian:/etc/hosts ./hosts    # Copy files/dirs host <-> container
podnext sync ./src debian:/root/src -d    # Sync directories (sha256 hashing + prune)
podnext rename debian deb-prod            # Rename installed container
podnext reset deb-prod                    # Reset container to initial clean state
podnext remove deb-prod                   # Remove container and its data
podnext search debian                     # Search OCI images on Docker Hub
podnext info                              # Show system & host kernel info

========================================================================
2. INTERMEDIATE: IMAGES, STORAGE, VOLUMES & BACKUP:
========================================================================
podnext image ls                          # List local image cache
podnext image pull alpine:latest          # Pull OCI image from registry
podnext volume create my-vol              # Create persistent storage volume
podnext volume ls                         # List storage volumes
podnext volume prune                      # Remove unused volumes
podnext network create isolated-net       # Create isolated bridge network
podnext network ls                        # List container networks
podnext backup create debian              # Create container snapshot archive (tar.gz)
podnext backup list                       # List backup snapshots
podnext backup restore <id> --target deb2 # Restore container from backup

========================================================================
3. ADVANCED: SYSTEM SERVICES, DAEMON & SUPERVISOR:
========================================================================
podnext daemon start                      # Start PDN supervisor daemon
podnext daemon status                     # Check supervisor daemon status
podnext service start web-srv             # Start managed service (with restart policy)
podnext service status web-srv            # Show service status & PID
podnext service logs web-srv              # View service logs
podnext quota set web-srv memory 512M     # Set memory cgroup quota
podnext quota set web-srv cpu 200         # Set CPU quota limit (2 cores)
podnext quota usage web-srv               # Monitor real-time resource usage
podnext watchdog status                   # Monitor circuit breaker & watchdog
podnext log tail web-srv                  # Stream logs in real-time
podnext dbus serve --socket $PREFIX/tmp/pn-dbus.sock  # Run IPC D-Bus broker
podnext dbus call ...                     # Send D-Bus method call
podnext gitops sync                       # Synchronize declarative GitOps manifests
podnext gitops status                     # Check GitOps app sync status
podnext boot enable web-srv               # Enable auto-start on Termux boot
podnext wakelock acquire web-srv partial  # Acquire Android wake lock to keep active

========================================================================
4. DIRECT EXECUTION MODE (Pure compatibility like proot binary):
========================================================================
podnext -r /path/to/rootfs -- /bin/bash    # Run custom rootfs directly
podnext -b /host/dir:/guest/dir -- ls      # Directly bind mount host directory

===== podnext attach --help =====
Reconnect to a session started with `podnext run --detach <container>`. `attach` never starts a session: with none running for the container it exits 1 and names the command that starts one. The argument is the container name, not a session id.

Ctrl-P Ctrl-Q detaches again and leaves the guest running; the same guest shell answers the next attach. Two declared simplifications: a resize of this terminal while attached is not re-forwarded to the guest, and output produced while detached is appended to the session log but not replayed on reconnect.

Arguments:

          Container name
