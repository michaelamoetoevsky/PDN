## Summary

`podnext install <image> --name ""` accepts an **empty container name**. It creates a container
whose rootfs lands at `~/.podnext/containers/rootfs`. That path is a directory with no sibling
and no name segment. The container is listed with a blank NAME column. The user **cannot remove
it through the CLI**. The container is thus an unremovable orphan. The orphan also blocks the
installation of a container whose directory collides with it.

## Reproduction

```sh
podnext install debian:13 --name ""
# Installing 'debian:13' as ''...
# [1/4] Authenticating with Docker Hub registry...
# [4/4] Configuring guest environment, DNS, and /dev/shm...
# Container '' installed successfully!
# Rootfs: /data/data/com.termux/files/home/.podnext/containers/rootfs

podnext list
# | NAME | DISTRO | VERSION | ARCH | STATUS | CREATED |
# |      | debian | 13      | aarch64 | Stopped | ... |

podnext remove -f ""
# Error: Container '' not found
```

## Root cause

`crates/podnext/src/main.rs:1851`

```rust
async fn cmd_install(image: String, name: Option<String>, force: bool) -> Result<()> {
    let container_name = name
        .clone()
        .unwrap_or_else(|| image.split(':').next().unwrap_or(&image).to_string());
    let _rootfs: PathBuf = install_image_native(&image, &container_name, force, None).await?;
```

No guard rejects an empty `--name` that the user supplies explicitly. Later, the code derives
the container directory when it joins the name onto the containers root. An empty segment
collapses to the containers root itself. Thus the code creates `rootfs/` one level too high.
Lookup paths then use a non-empty name and never match.

## Impact

- The orphan container consumes disk and is invisible to normal lifecycle commands.
- It blocks a later `install` at the same path with "already exists".

## Proposed fix

Validate the container name before any download. Reject empty values and whitespace-only
values. Enforce a safe charset, `[A-Za-z0-9._-]+`, with no path separators. Then exit with a
clear message. Add a regression test. The test must show that `install --name ""` exits non-zero
and creates nothing.
