## Summary

`podnext build local` is a stub: it rejects `ARG`, silently skips `RUN`, never produces a usable OCI image, and does not register the result in `podnext image ls`. The output looks like a build but nothing runnable is created.

## Reproduction

```sh
printf 'FROM alpine:3.24\nARG FOO=bar\nRUN echo hello\nCMD ["/bin/sh"]\n' > Dockerfile
podnext build local -t demo .
# Error: Unsupported Dockerfile instruction: 'ARG'
```

## Evidence: observed log

```
task-3 (power-user validation) reported:
  - `ARG` rejected: parser in `crates/proot-distro-core/src/dockerfile.rs` lacks `ARG`
    support (`Error: Unsupported Dockerfile instruction: 'ARG'`).
  - Builder incomplete: executes layer diff between context and an empty dummy directory,
    outputs a SHA-256 digest and size, deletes the tar.gz blob immediately
    (`crates/podnext/src/commands/mod.rs:2082`). Does not execute `RUN`, does not generate
    OCI manifests, does not register into `podnext image ls`.
```

## Root cause

In `crates/proot-distro-core/src/dockerfile.rs`, the instruction parser has no `ARG` token. In `crates/podnext/src/commands/mod.rs`, the build path diffs context against an empty directory and discards the blob. It does not execute `RUN` and does not emit a manifest.

## Impact

- The advertised OCI builder workflow cannot produce an image users can run.
- A success report for a build that produced nothing is worse than a failure.

## Proposed fix

Implement the missing steps: execute `RUN` in a scratch container, emit a real OCI manifest, and register the tag. Or make the command **fail loudly** and state that the builder is not implemented. Then no user mistakes the digest for a usable image.
